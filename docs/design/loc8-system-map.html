Everything, and how it fits together

Two devices, four apps, one 25-byte protocol. This is the visual companion to SYSTEM.md — every piece of hardware and software, how each talks to the next, and what state it's actually in.

Phones make the network → the Gateway makes it infrastructure → Command makes it operable → HQ makes it visible.
Remove any right-hand piece and everything to its left keeps working. That degradation order is the product.

01 The whole stack

Four layers, each surviving the loss of the one to its right

The only mandatory layer is the leftmost. Everything else adds reach, memory and visibility — and fails safe.

03 Coverage — how a festival is actually solved

04 The software — one engine, four doors

The core is built once and never forked

A capability built for one door is inherited by all four. That discipline is why the ops grammar can't drift and why encryption, when it lands, lands everywhere at once.

05 The protocol — 25 bytes, shared by everything

One frame format on every link in the system

Phone-to-phone, phone-to-anchor, across the LoRa trunk, into the Gateway, out to Command. Same bytes throughout — which is why a Linux port of the mesh is a port, not a redesign.

06 What a Gateway does for ordinary consumers

It fixes the hole a crowd of pocketed phones can't

Why this matters commercially

A venue that installs a Gateway for security simultaneously makes the consumer app work better inside its building — at zero additional cost or configuration. That is the natural opening for the SDK door: the venue's own app can embed the finder and inherit a mesh the venue already paid for.

07 One SOS, end to end

  1. FiredA guard holds the SOS button for one second. The phone broadcasts a type-7 frame carrying identity, position, floor and battery — 25 bytes.
  2. Through the crowdNearby phones hear it and relay. Each hop decrements TTL; each phone refuses to forward what it has already seen.
  3. Across the dead groundThe nearest anchor picks it up over BLE and puts it on the LoRa trunk — crossing the car park that has no phones in it.
  4. Into the recordThe Gateway, as trunk head-end, receives it and persists it at synchronous=FULL in the site database, with a hash-chained audit entry. This write never sheds — not even on battery.
  5. To the operatorsOver the venue LAN via mTLS, every Command console lights up. The console computes nearest responders by real haversine distance and dispatches.
  6. Back outStatus replies (codes 20–23: en route · on scene · need backup · clear) ride the same path in reverse, and the incident timeline fills in.
  7. Off-siteWhenever a pipe exists, the event stream reaches HQ. If not, it spools and backfills — the tile honestly shows "last synced" rather than pretending.

The one gate everything hangs on

The real Bluetooth mesh has never been run between two physical phones. The native module is 2,525 lines of written, never-executed Swift and Kotlin. Everything above — every app, every test, the entire Gateway thesis — assumes that radio works as designed.

Worse, the repository contradicts itself about it: CHANGELOG.md line 10 claims "mesh proven on 2 real iPhones" while line 87 of the same file lists the on-device matrix as "Not yet run." Reconciling that honestly is gate ②, and it must happen before this goes to anyone external.
